이 과정은 **집에 서버 한 대를 두고, 나와 가족만 쓰는 서비스를 올리는 것**이 목표입니다. 사진 백업, 비밀번호 보관, 광고 차단, 그리고 서버 안에서 일하는 클로드까지 한 대에 담습니다.

첫 챕터에서는 서비스를 올리기 전에 **바닥을 단단히 만듭니다.** 기기를 고르고, 설치하고, 공유기 뒤에서 항상 같은 자리에 있게 만들고, 정전이 나도 스스로 일어나게 합니다. 이 바닥이 흔들리면 이후 모든 서비스가 "가끔 접속이 안 돼요"로 돌아옵니다.

<Note type="why" title="이 챕터를 마치면">
- 우리 집 서버에 맞는 기기를 고르고, 전기료를 어림해 볼 수 있다
- Ubuntu Server 24.04 LTS를 설치하고 첫 점검을 마칠 수 있다
- 공유기에서 서버의 집 안 주소(IP)를 고정할 수 있다
- 우리 집 인터넷이 **외부에서 직접 들어올 수 있는 구조인지(CGNAT 여부)** 확인할 수 있다
- 정전이나 재부팅 뒤에도 서버가 스스로 돌아오게 만들 수 있다
</Note>

<Note type="tip" title="선수 지식과 환경">
입문 과정(12챕터)을 마친 것으로 보고 설명합니다. 이 챕터의 모든 설명은 **집 안 공유기에 연결해 쓰는 서버**를 기준으로 합니다. 월정액 임대 서버(VPS)를 쓰는 경우 1.4~1.5절은 건너뛰어도 됩니다. VPS는 이미 공인 주소를 가지고 있고, 가족 서비스는 집 안에서 쓰는 것이 기본이라 이 과정은 집 서버를 권합니다.
</Note>

## 1.0 이 서버가 하게 될 일

앞으로 올릴 것들입니다. 이 목록이 기기 선택의 기준이 됩니다.

| 영역 | 서비스 | 서버에 요구하는 것 |
|---|---|---|
| 서버 속 클로드 | Claude Code | 안정적인 인터넷, 메모리 여유 |
| 사진·파일 | Immich 또는 Nextcloud | **디스크 용량**, 메모리 |
| 비밀번호 | Vaultwarden | 가볍다. 대신 **백업이 생명** |
| 광고 차단 | AdGuard Home | 가볍다. 24시간 켜져 있어야 함 |
| 스마트홈 | Home Assistant | 가볍다. 안정성 |
| 영상 | Jellyfin | CPU(영상 변환), 디스크 용량 |

가볍게 시작해서 하나씩 올리는 것이 좋습니다. 처음부터 전부 올리려 하지 말고, 이 챕터에서는 **빈 서버 한 대를 안정적으로 세우는 것**만 합니다.

<Note type="warn" title="서버는 가족의 생활 기반이 됩니다">
광고 차단(DNS)을 서버로 돌리기 시작하면 서버가 꺼진 순간 **집 전체의 인터넷이 안 되는 것처럼 느껴집니다.** 사진 백업이 서버에 쌓이기 시작하면 서버 디스크 한 장이 가족 사진의 유일한 사본이 될 수도 있습니다. 그래서 이 과정은 설치 챕터부터 안정성과 백업을 앞에 둡니다. 백업은 Chapter 17에서 따로 다루지만, 소중한 자료를 올리기 전에 반드시 그 챕터를 먼저 끝내세요.
</Note>

## 1.1 기기 고르기

### 후보 비교

| 기기 | 장점 | 단점 | 추천 상황 |
|---|---|---|---|
| 소형 데스크톱(미니PC) | 조용하고 저전력, 성능 대비 가격이 좋다, 대부분 SSD 사용 | 처음 사려면 비용이 든다 | **가장 무난한 선택** |
| 쓰던 노트북 | 공짜, 배터리가 내장 UPS 역할을 하는 효과, 화면과 키보드가 있다 | 덮개를 닫으면 꺼지는 설정 해제 필요, 오래된 배터리는 부풀 수 있다 | 처음 시험해 볼 때 |
| 라즈베리파이 | 전기를 거의 안 쓴다, 작다 | 사진·영상 서비스는 성능이 빠듯하다, SD카드는 쉽게 닳는다 | 광고 차단·스마트홈처럼 가벼운 용도 |
| 중고 데스크톱 | 싸고 확장하기 좋다 | 전기를 많이 쓰고 소음이 있다 | 디스크를 여러 개 달 때 |

### 권장 최소 사양

이 과정 전체를 한 대로 하려면 아래를 권합니다. 이 값은 이 과정의 권장이며, **각 서비스의 실제 요구 사양은 해당 챕터에서 공식 문서로 다시 확인합니다.**

| 항목 | 권장 | 이유 |
|---|---|---|
| 메모리 | 8GB 이상 | 서비스 여러 개와 클로드를 동시에 돌린다. 4GB는 서비스를 2~3개로 줄여야 한다 |
| 시스템 디스크 | SSD 128GB 이상 | 운영체제와 서비스 설정. 하드디스크는 부팅과 응답이 느리다 |
| 자료 디스크 | 사진·영상 양에 맞게 별도로 | 시스템과 자료를 분리해 두면 재설치가 쉽다 |
| 네트워크 | **유선 랜 포트** | 와이파이는 끊기고 느려질 수 있다 |

<Note type="tip" title="자료용 디스크는 나중에 붙여도 됩니다">
지금은 시스템 디스크 하나로 시작하고, 사진이 쌓이기 시작할 때 외장 디스크나 내장 디스크를 추가하는 방법도 됩니다. 단, 외장 디스크를 쓸 때는 전원이 따로 필요한지, 서버가 재부팅될 때 자동으로 인식되는지 확인해야 합니다(Chapter 17에서 연결합니다).
</Note>

### 전기료 어림하기

서버는 24시간 켜 두므로 **소비 전력이 곧 연간 비용**입니다. 아래는 어림값이고, 정확한 값은 콘센트용 전력계로 직접 재 보세요.

| 평균 소비 전력 | 1년 사용량 | 1년 요금 (1kWh당 200원으로 가정) |
|---|---|---|
| 10W (저전력 미니PC, 라즈베리파이 위쪽) | 약 88kWh | 약 17,500원 |
| 20W (일반 미니PC, 노트북) | 약 175kWh | 약 35,000원 |
| 50W (데스크톱) | 약 438kWh | 약 87,600원 |

계산식은 `소비 전력(W) × 24시간 × 365일 ÷ 1000`입니다. (자체계산) 가정용 전기 요금은 사용량에 따라 단가가 달라지는 누진제이므로 실제 요금은 달라질 수 있습니다.

<Mini title="우리 집 후보 기기의 전기료 계산해 보기">
후보 기기의 평균 소비 전력이 15W라면 1년 사용량은 몇 kWh일까요?

<Answer>
`15 × 24 × 365 ÷ 1000 = 131.4`, 약 131kWh입니다. 1kWh당 200원이라면 약 26,300원입니다. 같은 기기를 하루에 8시간만 켠다면 3분의 1이 되지만, 서버는 가족이 언제 쓸지 모르므로 24시간 켜 두는 것을 전제로 생각해야 합니다.
</Answer>
</Mini>

## 1.2 Ubuntu Server 설치

### 어떤 버전을 받을까

입문 과정과 같은 **Ubuntu Server 24.04 LTS**를 씁니다. LTS(장기 지원판)는 보안 업데이트가 5년 보장되므로 서버로 오래 돌리기에 알맞습니다. 이 글을 쓴 2026년 11월 현재 24.04 계열의 최신 점검판은 24.04.5입니다. 받는 시점에 따라 숫자가 다를 수 있고 어느 쪽이든 괜찮습니다. 받은 뒤 `apt upgrade`로 최신으로 맞추기 때문입니다.

받는 곳은 Ubuntu 공식 사이트(ubuntu.com/download/server)입니다. **Desktop이 아니라 Server**를 받으세요.

<Hist year="1990s" title="왜 집 서버는 공유기 뒤에 있나 — 주소가 모자랐다">
인터넷 주소(IPv4)는 약 43억 개뿐입니다. 1990년대 중반에 이미 모자랄 것이 분명해졌고, 해결책으로 **한 집(회사)이 공인 주소 하나를 받아 내부 기기들은 사설 주소를 나눠 쓰는 방식**(NAT)이 널리 퍼졌습니다. 우리 집 공유기가 바로 이 일을 합니다.

그 결과 집 안의 기기는 밖으로 나가는 것은 쉽지만, **밖에서 집 안의 기기로 들어오는 것은 기본적으로 막혀 있습니다.** 보안에는 좋은 구조이지만, 집 서버를 밖에서 쓰고 싶을 때는 걸림돌입니다. 이 과정이 Chapter 2에서 공유기 구멍을 내는 방법 대신 다른 길을 쓰는 이유입니다.
</Hist>

### 설치 USB 만들기

1. 4GB 이상 USB 메모리를 준비합니다. **안의 내용은 전부 지워집니다.**
2. 받은 ISO 파일이 손상되지 않았는지 확인합니다. 파일 이름은 받은 버전에 따라 다릅니다.

<Term title="체크섬 확인" code={String.raw`
# 윈도우 (파워셸)
PS C:\Users\me\Downloads> Get-FileHash .\ubuntu-24.04.5-live-server-amd64.iso -Algorithm SHA256

# 맥 / 리눅스
$ shasum -a 256 ubuntu-24.04.5-live-server-amd64.iso
`} />

출력된 긴 문자열을 Ubuntu 다운로드 폴더에 있는 `SHA256SUMS` 파일의 같은 파일 이름 줄과 비교합니다. **한 글자라도 다르면** 다시 받습니다.

3. USB에 굽습니다. 윈도우는 Rufus, 맥은 balenaEtcher가 쉽습니다. 라즈베리파이는 SD카드나 SSD에 Raspberry Pi Imager로 Ubuntu Server를 바로 설치합니다(이 경우 아래 설치 화면 대신 Imager의 설정 창에서 이름, 계정, SSH를 정합니다).
4. 서버가 될 기기에 USB를 꽂고 전원을 켜면서 부팅 메뉴 키를 누릅니다. 제조사마다 F2, F10, F12, Del, Esc 중 하나입니다. USB를 첫 부팅으로 고르면 설치가 시작됩니다.

### 설치 화면에서 정할 것

| 화면 | 선택 | 이유 |
|---|---|---|
| Language | **English** | 오류 메시지를 영어 그대로 검색해야 자료가 많이 나온다 |
| Installer update | 새 설치기가 있으면 업데이트 | 최신 설치기가 버그가 적다 |
| Keyboard | 한국어 키보드 | 서버에 키보드를 직접 연결해 쓸 때만 중요하다 |
| Type of install | Ubuntu Server (기본) | minimized는 도구가 줄어 처음엔 불편하다 |
| Network | 유선, DHCP 그대로 | 고정은 1.4절에서 **공유기에서** 한다 |
| Proxy · Mirror | 기본값 | |
| Storage | Use an entire disk | 서버 전용 기기이므로 전체를 쓴다. 디스크 안의 기존 자료는 지워진다 |
| Profile | 이름, 서버 이름(예: `homeserver`), 사용자 이름, 비밀번호 | 사용자는 `root`가 아닌 일반 계정 |
| SSH | **Install OpenSSH server 체크** | 설치 후부터는 모니터 없이 다른 컴퓨터에서 접속한다 |
| Featured snaps | **아무것도 고르지 않는다** | 다음 챕터에서 Docker를 우리가 직접 설치한다 |

<Note type="warn" title="저장소 화면에서 확인할 것 · LVM과 디스크 크기">
기본 설정에서는 디스크를 논리 볼륨(LVM)으로 쓰는데, 설치 직후 `/`(루트)가 **디스크 전체보다 작게** 잡히는 경우가 있습니다. 설치 뒤 `df -h /`로 확인하고 디스크보다 많이 작다면 아래 명령으로 남은 공간을 모두 붙입니다.

<Term code={`
$ df -h /
$ sudo lvextend -r -l +100%FREE /dev/ubuntu-vg/ubuntu-lv
`} />

`-r`은 파일시스템 크기도 함께 늘리는 옵션입니다. 입문 Chapter 6에서 본 LVM을 그대로 쓰는 장면입니다.
</Note>

<Note type="danger" title="관리자 비밀번호는 한 곳에만">
이 서버의 일반 계정은 `sudo`로 **서버 전체의 관리자 권한**을 가집니다. 비밀번호를 쉬운 것으로 하지 말고, 메신저나 메모 앱에 적어 두지 마세요. 아직 비밀번호 관리 서비스가 없으니 지금은 종이에 적어 안전한 곳에 두고, Chapter 12에서 Vaultwarden이 생기면 옮깁니다.
</Note>

설치가 끝나면 **USB를 뽑고** 재부팅합니다.

## 1.3 첫 접속과 기본 점검

### 서버에서 직접 로그인해 점검

처음 한 번은 서버에 모니터와 키보드를 연결해 로그인합니다. 아래 명령은 입문 과정에서 쓴 것과 같습니다.

<Term title="homeserver" code={`
$ sudo apt update
$ sudo apt upgrade -y
$ sudo timedatectl set-timezone Asia/Seoul
$ timedatectl
$ hostnamectl
$ ip -br a
$ df -h /
$ free -h
`} />

| 명령 | 확인하는 것 |
|---|---|
| `apt update` · `apt upgrade` | 설치 직후 밀린 보안 업데이트를 받는다 |
| `timedatectl set-timezone Asia/Seoul` | 시간대를 한국으로. 로그와 예약 작업 시각이 틀어지지 않게 한다 |
| `hostnamectl` | 서버 이름과 운영체제 버전 |
| `ip -br a` | 집 안 주소(IP) 한 줄 요약. 1.4절에서 쓴다 |
| `df -h /` | 디스크 용량 |
| `free -h` | 메모리 |

커널이 갱신되었다면 `sudo reboot`으로 한 번 다시 시작합니다.

### 다른 컴퓨터에서 접속

서버의 주소를 알았으니, 이제 모니터를 치우고 평소 쓰는 컴퓨터의 터미널에서 접속합니다. 윈도우는 터미널(파워셸), 맥은 터미널 앱입니다.

<Term title="내 컴퓨터" code={`
$ ssh 사용자이름@192.168.0.50
`} />

주소는 `ip -br a`에서 본 값으로 바꾸세요. 처음 접속하면 서버의 지문을 신뢰할지 묻고, `yes`를 입력합니다(입문 Chapter 7). 접속이 되면 서버의 모니터와 키보드는 이제 필요 없습니다. **이후 모든 작업은 SSH로 합니다.**

## 1.4 공유기 안에서 서버의 주소 고정하기

### 왜 고정해야 하나

공유기는 연결된 기기에 집 안 주소를 **빌려줍니다.** 그래서 서버를 껐다 켜면 주소가 바뀔 수 있습니다. 주소가 바뀌면 사진 앱이 서버를 못 찾고, 광고 차단(DNS) 설정이 깨지고, 가족 모두에게 "안 돼요"가 번집니다.

해결 방법은 두 가지입니다.

| 방법 | 설명 | 이 과정의 선택 |
|---|---|---|
| 서버 안에서 고정 (netplan) | 서버가 자기 주소를 직접 정한다 | 공유기가 같은 주소를 다른 기기에 줘서 **충돌**할 수 있다 |
| **공유기에서 예약 (DHCP 예약)** | 공유기가 "이 기기에는 항상 이 주소"라고 정한다 | **채택.** 서버는 설정이 필요 없고, 한 곳에서 관리한다 |

### DHCP 예약 방법

공유기 관리 화면 이름은 제조사마다 다르지만 순서는 같습니다.

1. 서버에서 `ip -br a`로 주소를 확인하고, `ip link`로 **MAC 주소**(`link/ether` 옆의 xx:xx:xx:xx:xx:xx)를 적어 둡니다.
2. 공유기 관리 화면에 접속합니다. 주소는 보통 `192.168.0.1` 또는 `192.168.1.1`이고, 공유기 뒷면 스티커에 적혀 있습니다. `ip route`의 `default via` 옆 주소가 공유기 주소입니다.
3. 메뉴에서 **"DHCP 예약", "고정 IP 할당", "주소 예약"** 같은 항목을 찾습니다. (기기·통신사마다 이름이 다릅니다.)
4. 연결된 기기 목록에서 서버를 고르고 **현재 주소 그대로** 예약합니다. 주소가 공유기의 자동 배정 범위 밖으로 가야 하는 기종도 있어서, 화면 안내를 따릅니다.
5. 서버를 재부팅하고 같은 주소를 받는지 확인합니다.

<Term title="homeserver" code={`
$ ip route
default via 192.168.0.1 dev enp3s0 proto dhcp src 192.168.0.50 metric 100
192.168.0.0/24 dev enp3s0 proto kernel scope link src 192.168.0.50
`} />

`default via` 뒤가 공유기이고, `src` 뒤가 서버의 집 안 주소입니다.

<Note type="tip" title="공유기 화면을 못 찾겠다면">
통신사가 빌려준 공유기 겸용 장비는 일반 사용자에게 설정 화면을 제한하는 경우가 있습니다. 이럴 때는 통신사 안내나 고객센터의 "공유기 설정" 안내를 확인하세요. 제조사 모델 이름으로 검색하면 DHCP 예약 방법이 나오는 경우가 많습니다. 어떤 방법으로도 안 될 때만 서버 안에서 고정하는 방법(netplan)을 쓰고, 그때는 공유기가 자동으로 나눠 주는 범위 밖의 주소를 고르세요.
</Note>

<Note type="warn" title="유선으로 연결합니다">
와이파이로 연결한 서버는 신호가 흔들리면 끊기고, 절전 기능으로 응답이 늦어지기도 합니다. 서버는 반드시 **공유기에 랜선으로** 연결하세요. 공유기에서 먼 곳이라면 전력선 랜이나 콘센트형 랜 어댑터도 대안입니다.
</Note>

## 1.5 우리 집 인터넷은 밖에서 들어올 수 있나 — CGNAT 확인

### 왜 확인하나

집 서버를 밖에서 쓰는 가장 흔한 방법은 "공유기에서 포트를 열어 서버로 전달"하는 포트포워딩입니다. 그런데 통신사가 **여러 집이 공인 주소 하나를 나눠 쓰게 하는 경우**(CGNAT)에는 우리 공유기가 받은 주소 자체가 사설 주소라서 포트포워딩이 **아예 불가능**합니다.

이 과정은 포트포워딩을 쓰지 않으므로 어느 쪽이든 문제없이 진행됩니다. 그래도 지금 확인하는 이유는, **우리 집 환경을 정확히 알아야 Chapter 2의 선택이 납득되기 때문**입니다.

<Hist year="2012" title="CGNAT 전용 주소 대역이 따로 생겼다">
IPv4 주소가 바닥나자 통신사들은 가입자 여러 명에게 공인 주소 하나를 나눠 쓰게 했습니다. 이를 위해 **100.64.0.0/10** 대역(100.64부터 100.127까지로 시작하는 주소)이 통신사 전용으로 따로 지정되었습니다(RFC 6598). 이 대역의 주소를 공유기가 받았다면 CGNAT 안에 있다는 뜻입니다.
</Hist>

### 확인 방법

<Lab id="1-1" title="우리 집이 CGNAT 안에 있는지 확인" time="10분">

1. 서버에서 **밖에서 보이는 주소**를 확인합니다.

<Term title="homeserver" code={`
$ curl -s https://ifconfig.me ; echo
203.0.113.25
`} />

2. 공유기 관리 화면에서 **인터넷(WAN) 쪽 주소**를 확인합니다. 메뉴 이름은 "WAN", "인터넷 상태", "외부 IP" 등입니다.
3. 두 주소를 비교합니다.

| 결과 | 의미 |
|---|---|
| 1번과 2번이 **같다** | 공유기가 공인 주소를 직접 받는다. 다만 통신사가 주소를 바꿀 수 있어 **고정은 아니다** |
| 2번이 `100.64`에서 `100.127`로 시작 | CGNAT. 포트포워딩 불가 |
| 2번이 `10.`, `172.16`에서 `172.31`, `192.168.`로 시작하고 1번과 다름 | 통신사 장비 뒤에 공유기가 한 대 더 있는 구조(이중 NAT)이거나 CGNAT |

4. 결과를 서버 노트(1.7절)에 적습니다.

</Lab>

<Note type="tip" title="어떤 결과가 나와도 이 과정은 그대로 갑니다">
같은 주소이더라도 통신사가 며칠마다 바꾸는 경우가 흔합니다. 이것이 이 챕터 제목의 "고정 IP 없음"입니다. 우리는 공인 주소가 무엇이든 상관없는 방법(Chapter 2의 Tailscale)을 씁니다.
</Note>

## 1.6 정전과 재부팅에 대비하기

가정의 서버는 **정전, 공유기 재부팅, 누군가 콘센트를 뽑는 일**을 겪습니다. 이때 서버가 스스로 돌아와야 합니다.

### 전원이 돌아오면 자동으로 켜지게

1. 서버를 켜면서 BIOS(UEFI) 설정 화면으로 들어갑니다(보통 Del, F2).
2. **"Restore on AC Power Loss", "AC Back", "Power On after Power Failure"** 같은 항목을 찾아 **Power On**(또는 Last State)으로 바꿉니다. 항목 이름은 제조사마다 다릅니다.
3. 저장하고 나갑니다.

라즈베리파이는 전원을 연결하면 곧바로 켜지므로 이 설정이 필요 없습니다.

### 노트북을 서버로 쓸 때

덮개를 닫으면 절전으로 들어가므로 해제해야 합니다.

<Term title="homeserver" code={`
$ sudo mkdir -p /etc/systemd/logind.conf.d
$ printf '[Login]\\nHandleLidSwitch=ignore\\nHandleLidSwitchExternalPower=ignore\\n' | sudo tee /etc/systemd/logind.conf.d/lid.conf
$ sudo reboot
`} />

설정 파일을 직접 고치지 않고 **조각 파일을 추가하는 방식**입니다. 되돌리려면 파일을 지우고 재부팅합니다. 배터리 노트북은 오래 상시 충전하면 배터리가 부풀 수 있으니, 배터리 상태를 가끔 확인하세요.

### 재부팅 시험

<Mini title="재부팅 후 서버가 같은 자리에 돌아오는지 확인">
1. 서버에서 `sudo reboot`을 실행합니다.
2. 1분쯤 뒤 다른 컴퓨터에서 `ssh 사용자이름@서버주소`로 다시 접속합니다.
3. 접속 후 `uptime -p`와 `ip -br a`를 확인합니다.

<Answer>
`uptime -p`가 `up 1 minute`처럼 방금 켜진 시간을 보여 주고, `ip -br a`의 주소가 재부팅 전과 **같다면** DHCP 예약이 잘 되고 있는 것입니다. 접속이 안 된다면 공유기 화면에서 서버가 목록에 올라왔는지, 랜선이 꽂혀 있는지부터 확인하세요.
</Answer>
</Mini>

<Note type="warn" title="전원 플러그를 뽑는 정전 시험은 신중하게">
정전 시험은 서버에 **아직 소중한 자료가 없는 지금** 한 번만 해 보는 것이 좋습니다. 파일을 쓰는 중에 전원이 끊기면 자료가 손상될 수 있고, 최신 파일시스템은 이를 줄여 주지만 완전히 막지는 못합니다. 자료가 쌓인 뒤에는 정전 시험을 하지 마세요. 정전이 잦은 지역이라면 소형 UPS(무정전 전원장치)를 서버와 공유기에 연결하는 것이 가장 확실한 대비입니다.
</Note>

## 1.7 서버 노트와 마무리

서버가 늘어날수록 "그 비밀번호가 뭐였지", "어느 포트였지"가 반드시 생깁니다. 지금부터 한 장짜리 **서버 노트**를 만들어 두세요.

| 항목 | 예 |
|---|---|
| 서버 이름 | homeserver |
| 집 안 주소 | 192.168.0.50 (공유기에서 예약) |
| MAC 주소 | xx:xx:xx:xx:xx:xx |
| 공유기 관리 주소 | 192.168.0.1 |
| 관리 계정 이름 | (비밀번호는 적지 않는다) |
| 설치 날짜 · 버전 | 2026-11-15, Ubuntu 24.04.5 LTS |
| CGNAT 확인 결과 | 같은 주소 / CGNAT / 이중 NAT |
| 전력 (전력계로 잰 값) | 예: 평균 12W |

<Lab id="1-2" title="홈서버 바닥 만들기 · 체크리스트" time="1시간 안팎">

- [ ] Ubuntu Server 24.04 LTS를 설치하고 일반 계정으로 로그인했다
- [ ] `apt update`와 `apt upgrade`를 끝냈고 시간대가 Asia/Seoul이다
- [ ] `df -h /`로 디스크 크기가 맞는지 확인했다
- [ ] 다른 컴퓨터에서 SSH로 접속했다
- [ ] 공유기에서 서버 주소를 예약했고, 재부팅해도 같은 주소다
- [ ] 서버를 랜선으로 연결했다
- [ ] 우리 집이 CGNAT인지 확인하고 기록했다
- [ ] 정전 뒤 자동 시작을 설정했다(BIOS) 또는 해당 없음(라즈베리파이)
- [ ] 서버 노트를 만들었다

</Lab>

<Note type="why" title="이번 챕터에서 일부러 하지 않은 것">
- 공유기 포트포워딩과 DDNS: 밖에서 집 서버로 직접 들어오는 문을 만들면 그 문이 공격 대상이 됩니다. 가족만 쓰는 서버라면 문이 필요 없습니다.
- 방화벽과 보안 강화: 서비스를 올리기 전에 한 번에 정리하기보다, 서비스가 하나씩 늘 때마다 닫고 열고 점검하는 편이 실수가 적습니다. Chapter 18에서 정리합니다. 입문 Chapter 10에서 배운 기본(SSH 키 로그인, ufw)은 Chapter 2 이후에 적용합니다.
</Note>
