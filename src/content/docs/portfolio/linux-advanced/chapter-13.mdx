휴대폰, TV, 스마트 기기마다 광고 차단 앱을 따로 설치할 수는 없습니다. 대신 **집의 DNS를 서버가 맡으면** 집에 연결된 모든 기기가 광고와 추적 사이트의 이름을 찾는 단계에서 막힙니다. AdGuard Home이 그 일을 하는 프로그램입니다.

<Note type="danger" title="이 서비스는 집 전체 인터넷이 의존합니다">
DNS가 죽으면 인터넷은 연결돼 있어도 **웹사이트가 열리지 않는 것처럼** 보입니다. 서버가 꺼지거나 컨테이너가 멈추면 가족 모두가 "인터넷이 안 돼요"라고 말합니다. 이 챕터는 **설치보다 대비가 중요합니다.** 대비책(13.4절)을 읽고 시작하세요.
</Note>

<Note type="why" title="이 챕터를 마치면">
- DNS가 무엇이고, DNS로 광고를 막는 원리를 설명할 수 있다
- 포트 53 충돌을 해결하고 AdGuard Home을 설치할 수 있다
- 공유기에 DNS를 지정하고, 서버가 꺼졌을 때의 대비를 만들 수 있다
- 집 밖에서도 Tailscale로 광고 차단을 쓰는 방법과 위험을 설명할 수 있다
</Note>

## 13.1 DNS 차단의 원리

<Hist year="1983" title="인터넷의 전화번호부">
컴퓨터는 `example.com` 같은 이름이 아니라 숫자 주소로 통신합니다. 이름을 숫자로 바꿔 주는 전화번호부가 **DNS**이고, 1983년에 처음 설계됐습니다. 모든 접속은 먼저 "이 이름의 주소가 뭐죠?"라고 DNS에 묻는 일에서 시작합니다.
</Hist>

AdGuard Home은 집의 모든 기기가 던지는 이 질문을 받아서, **광고·추적 사이트 목록에 있는 이름이면 "그런 주소 없음"이라고 답합니다.** 광고가 아예 내려받아지지 않으므로 앱 안의 광고, TV의 광고, 스마트 기기의 추적까지 줄어듭니다.

| 할 수 있는 것 | 할 수 없는 것 |
|---|---|
| 광고·추적 도메인 차단 | 광고와 본문이 **같은 도메인**에서 오는 경우(일부 동영상 앞 광고) |
| 기기별 규칙(아이 기기 차단 목록) | 암호화된 DNS(DoH)를 직접 쓰는 앱이 우회하는 경우 |
| 어떤 기기가 어떤 이름을 묻는지 기록 | 바이러스 감지 같은 보안 소프트웨어 대체 |

## 13.2 설치

### 포트 53 충돌 해결

Ubuntu는 `systemd-resolved`가 이미 53번 포트의 일부(127.0.0.53)를 쓰고 있어 AdGuard가 시작하지 못합니다. 공식 문서가 안내하는 방식은 resolved의 임시 수신(stub)을 끄는 것입니다.

<Term title="homeserver (admin)" code={`
$ sudo mkdir -p /etc/systemd/resolved.conf.d
$ sudo tee /etc/systemd/resolved.conf.d/adguardhome.conf <<'EOF'
[Resolve]
DNS=127.0.0.1
DNSStubListener=no
EOF
$ sudo mv /etc/resolv.conf /etc/resolv.conf.backup
$ sudo ln -s /run/systemd/resolve/resolv.conf /etc/resolv.conf
$ sudo systemctl reload-or-restart systemd-resolved
`} />

이렇게 하면 서버 자신의 이름 풀이는 `127.0.0.1`(AdGuard)로 가게 됩니다. AdGuard가 아직 안 떠 있으면 서버가 이름을 못 풀 수 있으니, **설치를 한 번에 끝내고** 확인하세요.

### 컨테이너 올리기

`/srv/compose/adguard/compose.yaml`

```yaml
services:
  adguard:
    image: adguard/adguardhome
    container_name: adguard
    restart: unless-stopped
    ports:
      - "53:53/tcp"
      - "53:53/udp"
      - "127.0.0.1:13000:3000/tcp"
    volumes:
      - /srv/data/adguard/work:/opt/adguardhome/work
      - /srv/data/adguard/conf:/opt/adguardhome/conf
```

<Term title="homeserver (admin)" code={`
$ mkdir -p /srv/compose/adguard /srv/data/adguard/work /srv/data/adguard/conf
$ cd /srv/compose/adguard && docker compose up -d
`} />

관리 화면은 서버 안(127.0.0.1)에만 열려 있으므로, **내 노트북에서 SSH 터널**로 접속해 처음 설정합니다.

<Term title="내 노트북" code={`
$ ssh -L 13000:127.0.0.1:13000 사용자이름@homeserver
`} />

접속을 유지한 채 노트북 브라우저에서 `http://localhost:13000`을 엽니다.

### 설정 마법사에서 정할 것

| 항목 | 값 |
|---|---|
| 관리 웹 인터페이스 | 모든 인터페이스, **포트 3000** (compose의 안쪽 포트와 같다) |
| DNS 서버 | 모든 인터페이스, 포트 53 |
| 관리자 계정 | 긴 비밀번호로 새로 만든다 |

설정이 끝나면 Caddyfile에 3000 칸(안쪽 13000)을 추가해 tailnet에서 관리 화면에 들어옵니다. **관리 화면은 주인만** 들어올 수 있도록 Chapter 2의 가족 접근 규칙에서 3000을 빼도 좋습니다.

## 13.3 설정

관리 화면의 설정에서 정합니다.

| 설정 | 권장 |
|---|---|
| 상위 DNS 서버 | 암호화 DNS(DoH) 주소를 쓴다. 예: `https://dns.cloudflare.com/dns-query`, `https://dns.quad9.net/dns-query` 중 하나를 고른다. 어느 곳이든 **이름 질의 기록은 그 회사에 전달된다**는 점을 알고 고른다 |
| 필터 목록 | 기본 목록으로 시작한다. 목록을 많이 켤수록 정상 사이트가 막힐 가능성이 커진다 |
| 쿼리 기록 보관 | 7~30일로 줄인다. 가족이 어디를 방문했는지가 담기는 개인정보다 |
| 허용 목록 | 정상 사이트가 막히면 여기에 등록한다 |

<Note type="warn" title="쿼리 기록은 가족의 사생활입니다">
DNS 기록에는 **누가 어떤 사이트를 언제 찾았는지**가 남습니다. 관리자가 이 화면에서 가족을 감시하는 용도로 쓰지 않겠다는 약속을 가족과 하고, 기록 보관 기간을 짧게 하세요. 이 서버의 목표는 광고 차단이지 감시가 아닙니다.
</Note>

## 13.4 공유기에 연결하고 대비하기

### 연결

공유기의 DHCP 설정에서 **DNS 서버 주소**를 서버의 집 안 주소(`192.168.0.50`)로 바꿉니다. 메뉴는 "DHCP 서버", "DNS 설정" 등입니다. 기기가 다시 연결될 때(와이파이를 껐다 켤 때) 새 DNS를 받습니다.

확인은 서버에서 합니다.

<Term title="homeserver" code={`
$ dig @127.0.0.1 example.com +short
$ dig @127.0.0.1 doubleclick.net +short
`} />

첫 명령은 주소가 나오고, 둘째는 비어 있거나 `0.0.0.0`이 나와야 합니다. (`dig`가 없으면 `sudo apt install -y dnsutils`)

### 서버가 꺼졌을 때의 대비

| 대비 | 방법 |
|---|---|
| **보조 DNS 지정** | 공유기에 DNS를 2개 넣을 수 있다면 보조에 공개 DNS(예: 1.1.1.1)를 넣는다. 서버가 꺼져도 인터넷은 된다. 대신 보조로 넘어가는 기기는 광고가 보인다 |
| **복구 방법 문서화** | 공유기 화면의 DNS를 비우면 원래대로 돌아간다는 것을 서버 노트와 가족에게 알린다 |
| **감시** | Chapter 15의 Uptime Kuma로 DNS 응답을 감시하고 알림을 받는다 |
| **이 서비스의 업데이트와 재부팅은 시간대를 골라서** | 가족이 인터넷을 쓰지 않는 새벽에 한다 |

<Mini title="공유기가 보조 DNS를 못 받을 때">
공유기가 DNS를 하나만 받는다면, 서버가 꺼졌을 때 어떻게 대비할 수 있을까요?

<Answer>
공유기에서 DNS를 서버로 지정하는 대신 **기기마다 DNS를 지정**하는 방법이 있습니다(번거롭지만 일부 기기만 적용). 또는 서버 대신 **다른 항상 켜져 있는 기기**에 AdGuard를 하나 더 올려 DNS를 2대로 만드는 방법이 있습니다. 어느 쪽도 어렵다면, 처음에는 가족 일부(예: 내 휴대폰)만 DNS를 지정해 서버를 안정화한 뒤 공유기에 적용하세요.
</Answer>
</Mini>

## 13.5 집 밖에서도 광고 차단

Tailscale 관리 콘솔의 DNS 화면에서 **네임서버로 서버의 tailnet 주소(100.x.y.z)를 추가**하면, tailnet에 연결된 기기들은 어디서든 AdGuard를 DNS로 씁니다. AdGuard의 DNS가 tailnet 쪽에서도 응답하려면 서버의 53번이 tailnet 주소에서도 열려 있어야 하는데, 위 compose는 모든 주소에 열려 있어 가능합니다.

<Note type="danger" title="밖에서 서버가 꺼지면 인터넷이 안 됩니다">
집 밖의 휴대폰이 서버를 DNS로 쓰도록 강제하면, **서버가 꺼졌거나 집 인터넷이 끊긴 순간 그 휴대폰의 인터넷이 전부 멈춥니다.** 이 설정은 가족 모두에게 적용되므로 영향이 큽니다. 서버가 한 달 이상 안정적으로 돈 뒤에, **내 기기 한 대에서 먼저** 시험하세요. 문제가 생기면 콘솔에서 네임서버를 지우면 즉시 원래대로 돌아갑니다.
</Note>

<Lab id="13-1" title="광고 차단 도입" time="1시간 30분">

- [ ] 포트 53 충돌을 해결했고 AdGuard가 실행 중이다
- [ ] SSH 터널로 설정 마법사를 마쳤다
- [ ] 서버에서 `dig @127.0.0.1`로 차단 시험을 확인했다
- [ ] 내 기기 1대에서만 DNS를 지정해 하루 동안 써 봤다
- [ ] 정상 사이트가 막혀서 허용 목록에 넣은 경험을 했다(없다면 일부러 하나 시험)
- [ ] 쿼리 기록 보관 기간을 줄이고, 가족과 약속을 했다
- [ ] 보조 DNS와 복구 방법을 정했고 서버 노트에 적었다
- [ ] 공유기에 서버 DNS를 적용했다(1주일 시험 뒤)

</Lab>
